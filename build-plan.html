Technical plan · jiph.in rebuild

A campus that builds itself as you scroll

Plan for a new JIPH Furniture website: an interactive 3D campus where visitors watch classrooms, lecture halls, libraries and hostels assemble from the JIPH catalogue, backed by a product database and an enquiry system that hands every lead to the sales team.

Source: JIPH catalogue (136 pages)References: 2 Instagram reels, Scrolltide Firnlight & ValmoraPrepared 13 Oct 2026
01

Goals and audience

JIPH sells to institutions, not to individual shoppers. A sale starts with an enquiry, moves through drawings, samples and a site visit, and ends with a purchase order, often above ₹1 Cr. The website’s job is to create qualified enquiries and make the sales team’s first call easier.

Who visitsWhat they needWhat the site gives them
Principal / DirectorConfidence the vendor is big and reliable3D campus story, client list, factory and certifications
Admin / Purchase officerModel codes, sizes, finishes, quantitiesProduct pages with specs, search by code (e.g. 1102), quote basket
Architect / Interior consultantDimensions, layouts, CAD blocksDownloadable spec sheets and drawings per product
Government / tender buyerCompliance and past govt projectsGovt-project badges (UP, Delhi, A.P. school projects), ISO and ZED certificates

How we measure success

  • Qualified enquiries per month (institution name, size and timeline filled in)
  • Quote baskets submitted, site visits booked, catalogue downloads
  • Mobile Largest Contentful Paint under 2.5 s, even with the 3D experience on the page
  • Ranking for model and category searches such as “lecture hall seating manufacturer” and “hostel bunk bed supplier”

The 3D concept: “Build your campus”

Both reels show the same idea: an empty room that fills itself as you scroll, and an isometric 3D map with info cards. For JIPH this maps naturally onto the catalogue, because every catalogue chapter is a room on a campus.

Homepage storyThe home page opens on an empty classroom shell. As the visitor scrolls, the floor appears, rows of Scholar desks drop into place, the Mentor teacher table slides in, and the room is finished. The camera then pulls back to an isometric campus. Each building is a product range; tapping one opens that range.

Design system rules carried over from the audit

  • One H1 per page, real heading order, alt text on every image
  • Brand red only on actions; neutrals everywhere else
  • Left-aligned body text at 17 px; one font family plus a mono for model codes
  • Mobile: one bottom bar with Call and Enquire instead of floating buttons
  • WCAG 2.2 AA contrast, keyboard navigation, reduced-motion support

3D asset pipeline

We build roughly 20 hero models in 3D, not all 400 catalogue models. The rest use studio photography.

StepToolOutput
1. SourceFactory CAD (SolidWorks / AutoCAD / Cabinet Vision) or measured modellingAccurate geometry for each hero product
2. Clean-upBlenderLow-poly mesh (under 30k triangles per item), UVs, baked lighting
3. MaterialsBlender / SubstanceLaminate textures from the catalogue’s standard shades; powder-coat colours as swappable materials
4. ExportglTF with Draco geometry and KTX2 texturesUsually 300–800 KB per product
5. Scene rendersBlender CyclesImage sequences (about 90 frames per scene, WebP) for the Lite tier and still renders for SEO
Photography in parallelStudio shoot of every catalogue model on a seamless white background, front, three-quarter and detail angles. This replaces the current mix of banners with text baked into images.

07

Data model

Range

  • name, slug, segment (institutional / office)
  • campus building it belongs to
  • hero image, 3D scene, intro text
  • sort order

Product

  • model name (Scholar 90), code (1102, unique)
  • range, series, seater type
  • dimensions W × D × H in mm
  • materials, highlights, features
  • finishes allowed, images, 3D model, spec PDF, CAD file
  • tags: school, college, hostel, govt project
  • related products

Finish

  • type: laminate or powder coat
  • shade code and name (e.g. 638 Lorrian)
  • swatch image, texture for 3D
  • matte / semi-gloss / textured

Project

  • client, city, state, sector
  • year, seats or units supplied
  • products used (links to Product)
  • photos, testimonial

Lead

  • name, role, institution, phone, email, city
  • project type, size, budget band, timeline
  • source page, UTM, device tier
  • status, owner, Zoho ID
  • consent record (DPDP)

Quote request

  • lead reference
  • items: product, quantity, finish
  • generated PDF
  • status: new, contacted, quoted, won, lost

Also: Certification, Testimonial, Machine (infrastructure page), Office location, Site-visit booking, Download log, Blog post.

POST /api/revalidateCMS webhook that rebuilds changed pages

When a lead comes in

  1. Saved to PostgreSQL first, so nothing is lost if an outside service is down.
  2. Created as a Lead in Zoho CRM with source, products of interest and UTM fields. A retry queue covers Zoho outages.
  3. WhatsApp message to the assigned salesperson, and a WhatsApp confirmation to the buyer (template message, with their consent).
  4. Email confirmation to the buyer with the quote PDF attached, if one was requested.
No prices on the siteThe quote PDF lists models, codes, sizes, finishes and quantities only. Pricing stays with the sales team. A dealer price list can come later behind a login.
09

SEO and migration

  • Redirect map: 301 every old URL to its new page. Several current links are broken, for example /staff-office-tablestaff%20office%20table and /tablestables.
  • One page per model (about 400), each with a unique title such as “Scholar 90 Classroom Desk (1102) | JIPH”.
  • Structured data: Organization, LocalBusiness (Gharaunda plant), Product, BreadcrumbList, FAQ on guides.
  • Text outside the 3D: every scene’s copy is real HTML, so search engines and screen readers read it all.
  • Clean-up: remove the leftover template text (“Smart Digital Agency”, “Get Mobile App”), duplicate H1s and empty headings found in the audit.
  • Search Console: verify, submit XML sitemaps, monitor index coverage after launch.

Catalogue clean-up before import

The catalogue becomes the product database, so its data needs to be consistent. I found these while reading it:

Duplicate model codesCode 2612 is used for Focus-3, Wisdom-30 and Formula-1. Code 2904 is used for Linux-3 and all four Cozy sofas. Product codes must be unique to work as URLs and in the quote basket.
IssueWhereFix
Index page numbers all read “00-00”IndexFill in page numbers (or link chapters in the PDF)
Stats differ between catalogue and websiteMilestones page: “2 lakh+ sq ft of spaces”, “1.5 lakh sq ft” facilityAgree one set of numbers for both
“28+ years” since 1996Founder’s message30 years in 2026
“ISO 45001:2015” listedCertificationsISO 45001 was first published in 2018; check the certificate wording
Client name spellingProjects: “Bedford School”; website: “Beford School”Confirm the correct name
Typos“Pemium Chair’s”, “Traning”, “Autometic”, “Confrence”, “Gasli”, “Feflex”, “Boash”Correct during import
Scholar 214 / 228 named in other products’ textScholar 218 and Scholar 25 pagesCopy-paste errors; rewrite those descriptions

Import approach: extract text into a spreadsheet (one row per model: code, name, range, dimensions, materials, features), JIPH’s team checks it, then a script loads it into the CMS. Product images come from the new photo shoot rather than the PDF.
